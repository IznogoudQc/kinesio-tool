# 2026-07-31 — Questionnaire d'habitudes de vie (FANTASTIC)

## Demande

Marie veut « envoyer un PDF interactif par courriel ». Nicholas fournit le premier questionnaire en photo :
*Questionnaire sur la participation à des activités physiques favorables à la santé*.

En le transcrivant, il s'avère que c'est le **FANTASTIC** — instrument validé, 9 sections dont les initiales
donnent son nom, 25 énoncés, 5 colonnes cotées 0-4, total sur 100. Ce n'est donc pas qu'un formulaire à
recopier : il y a un résultat à calculer.

## Ce qui a été décidé, et pourquoi

**Pas de PDF remplissable.** Le moteur d'impression d'Electron rend du HTML en PDF *statique* — aucun champ
de formulaire possible. Ajouter `pdf-lib` était faisable, mais les lecteurs PDF des téléphones gèrent mal les
formulaires alors que tous ont un navigateur. → HTML autonome.

**Le retour des réponses est le vrai sujet.** Question posée à Nicholas avant d'écrire quoi que ce soit :
si Marie doit retaper les réponses, le formulaire papier fait aussi bien. Réponse : l'app doit relire le
fichier rempli. C'est ce qui a dicté toute l'architecture.

**Code de 30 caractères plutôt que du JSON encodé.** Un client sur téléphone recopie `FT1` + 25 chiffres +
2 de contrôle dans une réponse de courriel ; il ne recopie pas 300 caractères de base64 et n'arrive pas
toujours à joindre un fichier. Les deux chemins existent, le code est mis en avant.

**Somme de contrôle pondérée par position.** Une somme simple ne détecte pas l'inversion de deux chiffres
voisins — l'erreur de recopie la plus fréquente. Sans contrôle, l'import réussirait et écrirait de mauvaises
réponses dans le dossier : une erreur *silencieuse*, invisible jusqu'à ce qu'un score étonne Marie.

**Le client ne voit pas son score.** Décision prise contre la facilité : le FANTASTIC se lit avec un
professionnel. Cohérent avec la consigne de Marie de ne rien afficher qui décourage (cf. les victoires
absentes du dashboard). Verrouillé par un test.

**Score au prorata des énoncés répondus.** Compter un blanc comme un zéro donnerait un score catastrophique
et cliniquement faux à qui n'a pas tout rempli.

## Le piège de la duplication, traité de front

Le script inline de la page recopie forcément l'encodeur — une page isolée ne peut rien importer. C'est
exactement le genre de double source qui a coûté plusieurs correctifs cette session. Parade : un test
**extrait le script du HTML produit**, l'exécute et vérifie qu'il donne les mêmes codes que la version
TypeScript, sur 300 jeux de réponses. Une divergence casse les tests, pas un client.

## Une contrainte d'architecture découverte en route

Premier réflexe : générer le HTML dans le processus principal. Impossible proprement — `tsconfig.node` émet
du JavaScript, donc pas d'`allowImportingTsExtensions`, donc **tout module de `src/lib/` partagé avec le main
doit être autonome** (c'est le cas de `report-scope`, `client-folders`, `qaap` — vérifié : zéro import de
frère chez tous). Recopier les 25 énoncés côté Electron aurait créé la duplication qu'on venait d'éviter.

→ Le HTML est construit côté renderer ; le main ne fait qu'écrire les octets et les joindre au courriel.

## Vérification

- 481 tests (434 avant), 0 erreur de type sur les deux projets, lint à 0 erreur.
- **Aller-retour complet vérifié dans un vrai navigateur** : 25 énoncés remplis dans la page, code
  `FT1 01234 01234 01234 01234 01234 MJ` produit, collé tel quel (espaces compris) dans l'app → 25 réponses
  lues, 50/100, « Passable ». Un caractère modifié → refus avec message.
- `npm run build` passe, aucun `.js` parasite dans `src/`.
- **Non vérifié visuellement** : les écrans React dans l'app (formulaire de saisie, modale d'import, carte
  d'historique). Ils compilent et sont typés, mais n'ont pas été rendus — cela demanderait d'ouvrir une
  fenêtre Electron.

## Piste ouverte

Le FANTASTIC pourrait être le **« Questionnaire combiné »** de l'ancien logiciel, celui coté 2 dans le bilan
de Sabrina (cf. [[../decisions/0033-score-global-formule-confirmee]]). Un score sur 100 ramené sur 0-4 donnerait
ce genre de valeur. À confirmer si Marie retrouve une vieille feuille remplie avec la cote que le logiciel en
tirait — ce serait la dernière pièce du score global.

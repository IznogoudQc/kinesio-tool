## v0.9.29 — Étiquette du dernier point rognée sur les graphes de tendance

**Symptôme** (capture Marie / Nicholas) : la valeur du dernier point des courbes était coupée — « % » rogné
à droite sur le % de gras, « 4 / 4 » illisible en haut à droite sur le score de composition.

**Diagnostic** : l'étiquette (`textAnchor="middle"`) est centrée sur le dernier point, qui n'est qu'à

- `lastLabelX = Math.min(lastX, W - 24)` → plus de débordement à droite.
- `lastLabelY = lastLabelAbove ? lastY - 9 : lastY + 20` (bascule sous le point si `lastY - 20 < 0`).

## v0.9.30 — Indice de santé du dos : parité exacte (enquête + correctif)

**Demande** : « on va travailler sur l'indice du dos, est-ce que tu as maintenant toutes les informations

## v0.9.33 — Une seule feuille de saisie : la puissance des jambes aussi recalculée

**Question de Nicholas** : « je veux être sûr, quand on importe un vieux bilan, on copie seulement les
données nécessaires pour calculer les valeurs. Ça devrait être la même chose que la saisie manuelle. Lors

**Constat 1 — c'est déjà le cas pour le formulaire** : `ImportBilanModal` rend le **même** `BilanForm` que
la saisie manuelle (seul `variant="light"` change la palette). Rien à faire.

**Constat 2 — il restait UNE valeur dérivée recopiée** : la puissance des jambes. Le parser posait
`puissance_calculated_auto = false` (`bilan-parser.ts` l.165) et `computeBilan` avait une branche explicite
« préserver les valeurs importées ».

**Décision** : la puissance est un champ `type: 'computed'` du formulaire — Marie ne peut **pas** la saisir.
La seule source d'une valeur non-Sayers était donc l'import. Branche de préservation retirée : Sayers
s'applique dès que saut + poids sont connus, et la valeur importée ne sert plus que de repli si le calcul
est impossible. Idem dans `mergeComputedIntoBilan` (garde simplifiée).

**Preuve que Sayers est bien la formule d'origine** (`60.7 × saut + 45.3 × poids − 2055`) :

| Bilan | Saut | Poids | Sayers | Rapport |
|---|---|---|---|---|
| 2025-09 | 48 | 99,8 | **5380** | 5380 ✓ |
| 2011-08 | 42 | 99,2 | **4988** | 4988 ✓ |
| 2026-06 | 48 | 91,8 | **5017** | 4725 ✗ |

Le vieux rapport déclare lui-même utiliser Sayers ; pour juin 2026 sa valeur est incohérente avec le saut
et le poids qu'il imprime (il faudrait un saut de 43,2 cm ou un poids de 85,4 kg). C'est donc le rapport
d'origine qui est en défaut, pas notre calcul. **Effet visible** : ce bilan passera de 4725 à 5017 W.

**Tests** : puissance importée absurde (1234) écrasée par 5380 ; puissance conservée si le saut manque.

**Vérif** : tsc propre, `node --test` **331 pass**, `npm run build` OK.

## v0.9.41 — Score global : structure reconstituée + carte explicative

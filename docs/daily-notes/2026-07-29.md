# 2026-07-29

## v0.9.73 — Générer le rapport d'un vieux bilan

Nicholas : « j'aimerais quand on choisit la date d'un vieux bilan, que je sois capable de générer le HTML
et le PDF / et évidemment le "comparer à" fonctionne seulement avec des dates avant le rapport choisi ».

Jusqu'ici les deux boutons ignoraient la date sélectionnée : ils produisaient toujours le bilan de
synthèse. Marie pouvait consulter le bilan d'août 2011 à l'écran et obtenir un PDF de juin 2026.

**Le bilan choisi traverse maintenant toute la chaîne** : dashboard → service → preload → IPC →
`generateClientReportPdf` / `generateInteractiveReportHtml`. Le PDF le reçoit par l'URL de la fenêtre de
rendu (`/report/:id?bilan=…`), le HTML par son payload (`selectedBilanId`).

**Deux règles, pas une.** Le « comparer à » restreint aux dates antérieures n'est qu'une conséquence d'un
principe plus large : **un rapport ne montre rien de postérieur à sa date.** Sans ça, un document daté de
2011 aurait tracé des courbes montant jusqu'en 2026. L'historique entier est donc borné à la date du bilan
choisi — frise, avant/après, graphiques et sélecteur de comparaison.

Vérifié sur les cinq bilans de Nicholas : aucune fuite de donnée postérieure, quel que soit le bilan visé.
Le plus ancien n'a plus rien à quoi se comparer, ce qui est correct.

**Un rapport de synthèse reste le défaut** : sans sélection, comportement d'origine inchangé.

**Règle extraite dans `report-scope.ts`** plutôt que recopiée. Elle vivait déjà à quatre endroits
(ReportPage, payload Electron, EditorialReport, DashboardTab) — exactement la configuration qui a produit
les divergences de barème (v0.9.64-66) et de norme (v0.9.65). Neuf tests, dont un qui balaie tous les
bilans et vérifie qu'aucune date postérieure ne fuit.

Choix défensif : un `bilanId` introuvable renvoie l'historique **complet**, pas une liste vide — un rapport
trop fourni vaut mieux qu'un rapport vide.

**Vérif** : tsc web + node propres, `eslint` 0 erreur, `node --test` **387 pass** (9 ajoutés), build OK.
